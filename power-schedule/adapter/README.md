# Compact YASNO schedule adapter

This small Cloudflare Worker keeps full-provider JSON off the Garmin watch. It follows the public API and Kyiv-time semantics in [ha-yasno-outages](https://github.com/denysdovhan/ha-yasno-outages), MIT, commit `88f33db22cdddf4336937f4e15817792672c3d0f`. Attribution and the upstream license are in [THIRD-PARTY-LICENSE.txt](THIRD-PARTY-LICENSE.txt).

No Home Assistant, Android companion or YASNO token is required. One deployed adapter can serve both watches with independently selected groups.

## Deploy your instance

Install Node.js 22+ and use a Cloudflare account with Workers enabled. From this directory:

```sh
npm ci
npx wrangler login
npx wrangler deploy
```

Wrangler prints the deployed HTTPS URL. Put that **base URL**, without `/v1/schedule` or query parameters, into the Garmin app's Connect IQ settings.

Optionally restrict access:

```sh
npx wrangler secret put ACCESS_TOKEN
```

Enter a key at the prompt, then enter that same key in the watch app's **Adapter access key** mobile setting. The app sends it as a Bearer header; it never logs it. Without the secret, the adapter is public. Do not use your Garmin/DTEK password as this key. Consider account quotas when sharing a public deployment. Request logging is disabled by default in the included configuration.

The development workspace's dry run is not a deployment. No adapter URL is embedded in the app, and deployment requires your own authenticated Cloudflare session.

## API

- `GET /v1/catalog`: the verified region/provider pairs.
- `GET /v1/groups?region=25&dso=902`: current group strings.
- `GET /v1/schedule?region=25&dso=902&group=19.1`: selected group's compact schedule.
- With `ACCESS_TOKEN`, all routes require `Authorization: Bearer <key>`.

The upstream URL is fixed to YASNO's public planned-outages route for an allowlisted region/DSO. Requests cannot select an arbitrary remote URL. No street/house/address is collected. Upstream responses are limited to 1 MiB and time out after 15 seconds. Per-provider responses are cached for up to 60 seconds at each edge location, with concurrent requests coalesced. Cache hits retain the original upstream-check timestamp. Upstream errors never become empty/ON schedules.

The projected schema has `schema`, `region`, `dso`, `group`, `checkedAt`, `updatedAt`, `updatedLabel` and `days`. A day is `[Kyiv-date, startEpoch, endEpoch, status, slots]`; each slot is `[startEpoch, endEpoch, kind, startWallMinute, endWallMinute]`. Status: 0 NoOutages, 1 ScheduleApplies, 2 WaitingForSchedule, 3 EmergencyShutdowns, 4 unknown. Kind: 0 NotPlanned, 1 Definite. Epochs are integer UTC seconds; source minutes are Kyiv wall-clock minutes. Day lengths can be 23/24/25 hours.

Each day is limited to 64 source slots, at most two days, and the projected body is capped at 8 KiB. Invalid/overlapping slots, invalid dates, missing groups and unknown types never become inferred power availability. Gaps remain unknown. Unknown day statuses are explicitly unknown. The adapter ignores provisional/emergency slots when calculating confirmed state. Explicit NoOutages can establish a full non-outage day; contradictory Definite slots reject the response.

Current endpoints follow the reference repository. They are public website APIs, so schema/availability changes are possible. This is not a formal YASNO SLA or a measured electricity feed.

## Verify locally

```sh
npm test
npx wrangler deploy --dry-run
npx wrangler dev
```

Tests use synthetic fixtures and cover Kyiv DST (including repeated/nonexistent hours), minute 1440, status interpretation, scope isolation, malformed schedules, response bounds, authentication, failure handling and cache timestamps. The watch fixtures are generated by `node ../scripts/generate-fixtures.mjs` from the same normalizer.
